# 10 · 多工件并行操作设计

> 所属文档集：[00-OVERVIEW](./00-OVERVIEW.md)
> 问题：agent 能否同时操作多个工件（多个零件/装配体/工程图）？
> 关联：[07](./07-correctness.md)（generation 语义在此扩展）、[11](./11-fork-performance.md)（链式执行与亲和调度协同）

---

## 1. 需求本质：两类"多工件"

| 场景 | 例子 | 本质 |
|---|---|---|
| **A. 关联工件集**（真正的主流） | 一个装配体项目：3 个零件 + 1 个装配 + 1 张工程图 | **同一工程内的多文档协作**——建模零件 → 装配引用 → 出图，文档间有依赖 |
| **B. 独立并行任务** | 同时给两个不相干项目各建一个零件 | 真并行：追求吞吐 |

关键认知：**场景 A 才是 CAD 的真实工作流**（SolidWorks 本身就是"多文档工程"模型：装配体引用零件文档）。多工件支持不是"并行特性"，而是**补齐产品形态的必需品**。场景 B 是 A 的副产品。

---

## 2. 硬约束分析

| # | 约束 | 后果 |
|---|---|---|
| 1 | **COM STA 单线程**：一个 SW 实例内所有 API 调用串行 | 多工件≠COM 并行；单实例内的收益在于**上下文隔离与流水线交错**，不在真并行 |
| 2 | **ActiveDoc 全局唯一**：大量 API（尤其选择依赖流、部分 FeatureManager 操作）在非活动文档上不受支持/不可靠 | 跨文档操作需要"激活屏障"，激活有成本（~100–500ms + UI 闪动） |
| 3 | **命名按文档独立**："草图1"在每个文档里都存在 | 所有名称寻址必须限定在文档内；跨上下文的名称必须消歧 |
| 4 | **截图绑定活动窗口** | 非活动文档的截图困难，视觉闭环需要策略 |
| 5 | **SW 多实例受限**：需要注册表 EnableMultiProcess + 许可证允许；每实例 2–4GB 内存 + 独占许可席位 | 多实例是真并行但有现实成本，不能作为默认形态 |

---

## 3. 架构选项

### 选项 A：单 SW 实例 · 单 sidecar · 多文档（P2 推荐）

```
                    ┌─ sidecar（扩展）─────────────────────┐
cad agent ─通道B→   │ 串行队列（doc 亲和调度）               │
cad-worker×N ─B→   │ docs: Map<docId, DocState>            │
                    │   每doc: gen/特征树/草图上下文          │
主程序 ─通道C→      │ 激活管理器（亲和批 + 迟滞）           │
                    └──────────┬───────────────────────────┘
                               │ winax（单连接）
                        SolidWorks（多文档打开）
```

### 选项 B：多 SW 实例 · 多 sidecar（P3 扩展，真并行）

```
协调者 agent
 ├─ worker-1 → plugin 路由(target=sw1) → sidecar-1 :7654 → SW 实例 1
 └─ worker-2 → plugin 路由(target=sw2) → sidecar-2 :7655 → SW 实例 2
```

每个 sidecar 不变（单文档会话原样），并行度来自进程隔离。插件层加 target→port 路由；主程序负责 N 个 sidecar 的端口分配/令牌/生命周期。

### 对比与结论

| 维度 | A 单实例多文档 | B 多实例多 sidecar |
|---|---|---|
| COM 真并行 | ❌（队列串行） | ✅ |
| 上下文隔离 | ✅（靠 subagent） | ✅ |
| 崩溃隔离 | ❌（SW 崩全没了） | ✅（崩一个） |
| 内存/许可 | 1 席 | N 席 × 2–4GB |
| 装配体场景 | ✅ 天然（装配必须同实例） | ❌（跨实例无法引用） |
| 用户门槛 | 零 | 注册表+许可配置 |

**结论：P2 做选项 A（多文档），P3 做选项 B 作为吞吐扩展。场景 A（工程工件集）天然只能走选项 A。**

## 4. 选项 A 详设：单实例多文档

### 4.1 寻址与身份

- **docId**：sidecar 在文档打开时分配的稳定 ID（绑定 SW 文档对象 + 路径），跨激活/去激活不变
- 所有 `sw_*` 工具增加可选 `doc` 参数；**缺省 = 会话默认文档**（见 §5.2），模型不需要每次都填
- `sw_list_docs` 新工具：列出打开的文档（id/名/路径/类型/特征数/gen）

### 4.2 会话状态机改造

```
SessionState
├── globalGen          ← 文档打开/关闭/切换时 +1（"文档集合版本"）
└── docs: Map<docId, DocState>
    ├── gen            ← 该文档特征树/草图变化时 +1
    ├── path / title / featureCount / activeSketch ...
├── globalGen          ← 文档打开/关闭/切换时 +1（"文档集合版本"）
└── docs: Map<docId, DocState>
    ├── gen            ← 该文档特征树/草图/**选择集**变化时 +1（选择集是人机竞态最常见入口，归 per-doc gen）
    ├── path / title / featureCount / activeSketch
    ├── diagnostics    ← 分级诊断按文档隔离（[01](./01-harness-model.md) §4 引用）
    └── jobs           ← 每文档的长任务锁（全局仍最多一个后台 job）
```

generation 校验升级为 **(docId, docGen) 二元组**：操作携带的 expectedGen 只与目标文档的 gen 比对；globalGen 变化但目标文档未受影响时不拒收（避免过度保守——此为对 [07](./07-correctness.md) §3 单文档语义的**放宽**，"切文档不再必然拒收"）。人机竞态检测随之细化到每文档。

### 4.3 文档亲和队列调度（关键）

朴素 FIFO 在多文档下会导致**激活抖动**（activation thrashing：A,B,A,B…每次都要切 ActiveDoc，又慢又闪）。调度规则：

```
1. 队列元素 = (docId, op)
2. 亲和批（affinity batch）：连续同 docId 的操作直接执行，零切换
3. 迟滞：换文档执行前启动一个可配置的超时窗口 T（如 200ms），
   窗口内到达的同文档操作聚入当前亲和批（调度器不预测未来，只等待窗口）
4. 防饿死：任一文档等待 > T_max（如 2s）强制升级为队头
5. requiresActive 元数据：每个复合操作声明是否需要目标文档处于激活态；
   调度器在跨文档边界时自动插入 ActivateDoc2
```

与 [11](./11-fork-performance.md) §3.4 链式执行协同：一条操作链天然同 doc，整个链在一个亲和批内完成 = **零额外激活**。

### 4.4 激活策略与人机共存（产品决策）

agent 抢激活会打断正在 UI 里操作的用户。两种模式：

| 模式 | 行为 | 适用 |
|---|---|---|
| **follow（默认）** | requiresActive 的操作若目标文档非活动且用户正在交互（输入/鼠标空闲 < 阈值），挂起等待；空闲后执行 | 人机共用一台 SW |
| **auto** | 调度器自由激活 | 无人值守批处理 / SW 在工作站 |

用户可随时切换；主程序状态栏显示当前模式与挂起原因。

### 4.5 截图策略（约束 4 的应对）

- **焦点文档**（人在看 / agent 主交互对象）：现有事件触发截图流，不变
- **后台文档**：视觉闭环降档——截图合并进其亲和批（该文档批操作完成后、切走前拍一张）；批内中间步靠 state diff + 结果查证兜底
- 主程序多标签视图：每文档一个视图镜像 tab，后台 tab 暂停拉流（性能）

### 4.6 失败隔离

- 文档 A 的操作失败：只 bump A 的 gen，只影响绑定 A 的 worker；文档 B 的 expectedGen 校验照常通过
- worker A 的会话崩溃：不波及 worker B（opencode subagent 天然隔离）
- SW 进程崩溃：全部丢失 → 恢复流程按各文档最后保存路径自动重开（P2 记录 savedPath，P3 自动恢复）；要更强隔离才升级选项 B

## 5. opencode 层：协调者—工作者模式

### 5.1 角色结构

```
cad（primary，协调者）
 ├─ 解析用户工程需求 → 拆解为各工件的任务书（目标 + 约束 + 验收标准）
 ├─ 派发 cad-worker（subagent，每工件一个）
 ├─ 汇总 worker 结果 → 装配/出图阶段收回主线程执行
 └─ 自己只做轻量操作（sw_list_docs / 装配配合）

cad-worker（subagent，每工件一个）
 └─ 绑定单一 docId，专注建模，完成后返回摘要（特征清单+关键尺寸+截图1张）
```

为什么用 subagent 而不是单 agent 多文档上下文：

1. **上下文隔离**：工件 B 的截图不污染工件 A 的推理（注意力稀释是实测最大的多任务退化源）
2. **压缩局部化**：每个 worker 独立压缩，主线程保持干净（与 [11](./11-fork-performance.md) 图像 GC/压缩协同）
3. **失败重试局部化**：worker A 失败重跑不动 B 的上下文
4. 并行派发：opencode 的 task 机制天然支持多 subagent 并发——它们的工具调用在 sidecar 队列按 doc 亲和交错执行

### 5.2 会话绑定（免重复传 docId）

```
① 协调者派发时，任务书首行 = "绑定 docId=D3"
② worker 第一步调 sw_bind_session({doc: "D3"})（新工具）
③ 插件 tool.execute.before：此后该会话的所有 sw_* 调用自动注入 docId
④ worker 无需在每次调用里写 doc；写错目标的调用被插件拦截
```

实现落点全在插件层（session→doc 映射，钩子的 `context.sessionID` 已确认存在），sidecar 协议只多一个 doc 字段。

**缺省行为（fail-closed）**：未执行 `sw_bind_session` 的 subagent 会话发起写类 `sw_*` 调用时，插件直接拒绝（提示先绑定）——避免误落到任意文档；主会话（协调者）除外，它默认作用于活动文档。

### 5.3 名称消歧

- state 输出里的特征/草图名一律带文档前缀：`D3:草图1`
- `sw_get_state` 默认返回绑定文档；协调者可 `sw_get_state({all: true})` 看全局

## 6. 选项 B 详设：多实例（P3）

- **拓扑**：每 SW 实例一个 sidecar（sidecar 代码零改动，它本来就是单会话设计）；主程序分配端口/令牌/生命周期
- **路由**：插件维护 `target → base_url` 表；工具增加 `target` 参数（由 worker 绑定注入，同 §5.2 机制）；协议不变
- **agent**：协调者—工作者同构，worker 绑定 target 而非 docId
- **现实检查**（约束 5，**细节需核实**：`EnableMultiProcess` 注册表键名与许可证计席规则以 SW 官方文档为准）：注册表多实例开关、许可证席位 ×N、内存 ×N——定位为**团队工作站级部署选项**，不做消费级默认
- **典型用法**：夜间批处理工厂（8 个实例跑参数化变体）、SW 在专用工作站集群

## 7. 产品形态：Workbench（项目）

把"多工件"提升为产品概念：

```
Workbench（项目）= 工件集 + 派发关系
 ├── part: bracket_v2   (doc D1, worker)
 ├── part: shaft        (doc D2, worker)
 ├── assembly: 主装配   (doc D3, 协调者直辖——装配依赖零件完成)
 └── drawing: 装配图    (doc D4, drafting subagent，等 D3)
```

- 主程序：项目树侧栏（替代单一特征树）+ 每文档视图 tab + 每 worker 进度卡
- 协调者的派发顺序 = 依赖图（零件 → 装配 → 出图），天然映射到队列亲和（依赖图同层并行、跨层串行）
- 项目持久化：`*.cadwork`（JSON：工件清单 + 路径 + 派生关系）——主程序重启恢复整个 Workbench

## 9. 速查：多工件下的正确性增量

| 机制 | 单工件（01 文档） | 多工件（本文档） |
|---|---|---|
| generation | 单一计数 | globalGen（文档集合）+ 每文档 gen；expectedGen 按 (docId, docGen) 比对 |
| 串行队列 | 全局 FIFO | 全局串行 + doc 亲和批 + 迟滞 + 防饿死 |
| 原子性 | 复合操作内 | 不变（复合操作永远单文档内） |
| 人机共存 | generation 拒收 | + 激活策略（follow/auto）+ 焦点文档截图分档 |
| 失败隔离 | 单会话 | per-doc gen + per-worker 上下文；进程级隔离需选项 B |
